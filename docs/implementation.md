## 实现职责

- `document.ts`：可序列化素材记录、参数、修订号与 reducer；没有像素或文件内容。
- `imaging/AssetRepository` 与 `app/AssetContext`：持有原始文件和缩略 Blob，顺序导入，稳定 ID，删除即取消待办并撤销 URL；为五个工具共用。
- `layout.ts`：整数目标矩形、源裁切矩形、总尺寸和放大提示；三种布局共用同一输出计划。
- `inspect.ts`：JPEG SOF / EXIF、PNG IHDR / 动画块、WebP VP8 / VP8L / VP8X / 动画与 EXIF 头部检查。
- `decode.ts`：优先使用浏览器 `from-image` 方向处理，保留 HTMLImageElement 降级，避免手动二次旋转。
- `render.ts`：顺序解码、按计划绘制、释放解码缓存。预览使用小尺寸缩略 Blob，导出重新解码原图。
- `encode.ts`：检查编码 Blob MIME 和签名，然后重新解码核对输出尺寸。
- `render-engine.ts`：实际探测 Worker 的 PNG/JPEG 往返能力；任务结束或取消即终止 Worker，失败可退回主线程。
- `use-preview.ts`：80ms 调度、取消旧任务、禁止过期结果覆盖、撤销旧预览 URL。
- `ExportPanel`：点击时获取参数和文件引用快照，分阶段显示真实绘制/编码状态。取消后忽略不可中断调用的迟到结果。
- `download.ts`：根据实际格式确定后缀；下载 URL 保留 60 秒或至页面清理，页面只提示已生成并发起下载。

## 交互取舍

桌面三栏，平板将参数移到下方，手机采用单列折叠面板和带安全区的底部导出入口。原生按钮、表单、`details`、`dialog` 提供键盘交互；预览区域可聚焦滚动，图片列表和输出尺寸不依赖画面表达。

排序提供桌面原生拖动、触屏专用手柄与上下移动按钮。触屏处理代码已实现；触屏滚动冲突和系统保存仍需要真实设备验证。清空通过对话框确认，不删除用户的原始文件。

示例风景由本地 Canvas 绘制，不下载外部图片。没有第三方字体、统计或错误收集脚本。偏好读取/写入失败时继续使用默认设置。

## 已知限制与后续

- 当前保护值来自保守估算与本机自动化验证；没有跨设备的最大画布承诺。
- 五轮导入/清空检查了对象 URL 归零，但没有用真实手机验证浏览器整体堆内存或编码峰值。
- 性能样本为本地生成的纯色 PNG；不能代表相机照片、低端设备或真实手机性能。
- 没有服务端兜底、项目文件、撤销历史、PWA、自由拖动图层、多页海报。
- AVIF 输入限静态直接编码主图；动画、网格主图和带容器方向变换/显示裁切的输入拒绝。AVIF 有专项像素/内存预算，不保证任意尺寸或所有设备可编码。

新增职责落点：`imaging/watermark.ts` 负责样式归一化与几何，`draw-watermark.ts` 负责像素；`features/watermark/model.ts` 构造请求，Context 管理参数和 Logo，预览与批量 hook 分别处理失效、取消与结果。`imaging` 继续不依赖 React。原本只有拼接使用的素材仓库、导入面板和样式在出现第二个消费者后移到对应共享层，没有引入第三方依赖。

文字任务使用主线程与页面字体集，避免 Worker 的字体回退差异；图片水印保留 Worker 与主线程降级。系统字体跨设备不保证一致。批量点击时快照文件与参数，移除素材或替换 Logo 不影响已开始任务。成功结果逐项下载；独立水印页面保持原交互。ZIP、多步骤流水线在 V2.0 批量工具中提供，未引入云端存储或账户。

自动化与截图见 [V1.1 验收记录](verification.md#v11-水印实现验收)。本轮没有重新构建 Docker 归档、启动线上服务或进行真实手机验证。

职责分配：

- `imaging/transform.ts` 负责源裁剪矩形、尺寸和方向；`render.ts` 绘制同一计划，水印始终在最终方向绘制。
- `features/transform` 负责参数与原图选区；`features/convert` 负责格式检测和输出选择；`features/batch` 负责水印配置、命名和版本化模板。
- `features/processing` 为三个实际消费者共享配置快照、预览失效、任务与结果清单。成功项释放不再需要的原始请求引用；失败/取消项保留重试所需引用。
- `browser/render-queue.ts` 跨五个工具排队，避免多个完整尺寸画布并存；`ResultBudget` 统一核算结果 Blob，所有工具合计 64/32 MiB，新工具单批 32/16 MiB。
- `browser/zip.ts` 动态加载；按 Blob 流计算 CRC，ZIP32 存储模式复用原 Blob，不额外压缩图片，取消不会返回半成品。ZIP 加总大小受预算约束。
- AVIF 使用固定版 `@jsquash/avif@2.1.1` 单线程编码器，WebP 降级用 `@jsquash/webp@1.5.0`，无 COOP/COEP 前提，不加载多线程模块。WASM 由本站托管，许可随静态产物分发。
- 模板严格校验版本、字段、类型和范围；只在用户点击保存时持久化参数和水印文字。图片水印模板应用时清除现有 Logo 并要求重选。无图片或结果持久化。

本轮自动化与实测结果见 [验收记录](verification.md)。未进行真实 iOS/Android 设备、相机照片性能、整体内存峰值或线上部署验证；未重建原 V1.0 Docker 归档。Compose 源码构建标签更新为 2.0.0，旧归档可通过 `PICFORGE_IMAGE_TAG=1.0.0` 选择。

## EdgeOne Pages 部署支持

2026-11-05。新增根目录 `edgeone.json` 与 `.nvmrc`，固定 Node / pnpm，并提供 `pnpm build:edgeone` 构建命令。`deploy/prepare-edgeone.mjs` 将根配置中的响应头写入 `dist/edgeone.json`，供直接上传使用；`public/404.html` 随生产产物提供。保持现有 hash 路由、浏览器本地图片处理及通用/Docker 构建方式。

响应头沿用 Nginx 的 Worker/WASM CSP、nosniff、Referrer-Policy，入口重新验证缓存，带哈希资源长期缓存。相关浏览器用例分别验证两种部署配置的实际编码兼容性。步骤与上线核对见 [EdgeOne Pages 部署说明](edgeone-pages.md)，执行证据与线上边界见[验收记录](verification.md)。
